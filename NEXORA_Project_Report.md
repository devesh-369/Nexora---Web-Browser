# NEXORA — Search Engine Project

## 1. Objective
NEXORA is a web search engine built to demonstrate the core components of how
search engines like Google work: **crawling, indexing, ranking, and a search UI**.

## 2. Architecture
```
   Seed URLs
      |
      v
 [1] CRAWLER  ----> fetches pages, follows links, respects robots.txt
      |
      v
 [2] INDEXER  ----> builds an inverted index (word -> which pages, how often)
      |
      v
 [3] RANKER   ----> BM25 algorithm scores pages for a given query
      |
      v
 [4] WEB SERVER / UI --> Google-style search page (localhost:8000)
      |
      v
 [5] (OPTIONAL) EXTERNAL WEB API --> live results from the whole internet,
      used for the "Web" tab since crawling the entire internet is not
      feasible for a student project.
```

## 3. What is implemented (core, built from scratch)
- **Web Crawler**: starts from seed URLs, downloads pages, extracts text and
  title, follows internal links, obeys `robots.txt`, rate-limited requests.
- **Inverted Index**: maps every word to the list of pages it appears in and
  how many times — the same basic data structure real search engines use.
- **BM25 Ranking Algorithm**: a widely used relevance-ranking formula
  (improvement over plain word-count / TF-IDF) to order results by relevance.
- **Search UI**: Google-style home page and results page, built with plain
  HTML/CSS, including a results count, timing, and snippets with the
  matched keywords in context.
- **"My Index" tab**: shows results purely from NEXORA's own crawler+index
  (no external dependency) — this is the part that proves the search engine
  logic works end-to-end.
- **Customizable UI**: a settings panel (gear icon, top-right) lets the user
  switch between Light/Dark mode and 3 accent color themes (Blue, Purple,
  Green). The choice is saved in the browser so it's remembered next time.
- **Voice Search & Voice Answer**: uses the browser's built-in Web Speech API
  to let the user speak a query (auto-filled and searched) and to read the
  top result aloud — no external service or API key needed.
- **Deep Search Mode**: runs several related queries for one topic (overview,
  how it works, examples, pros/cons) and presents the combined results
  organized by angle, instead of a single flat list.
- **Fact Check Mode**: pulls multiple independent sources for a claim and
  shows them side by side for the user to judge. If an AI key is configured,
  it additionally shows an automatic Supported / Contradicted / Unclear
  verdict with a short reason.
- **Project Ideas Mode**: for a topic, shows project suggestions with
  difficulty, required concepts, a real-world use case, and GitHub/paper
  search hints — generated by an AI model when a key is configured, or a
  plain set of web resources otherwise (never fabricated/hardcoded content).
- **Full account system**: Email+Password signup & login (PBKDF2-hashed
  passwords), Forgot/Reset password, email verification (link-based),
  a Profile page (name, avatar, language, saved search history, bookmarks),
  and a Security page with active sessions, "logout from all devices",
  login activity log, and real TOTP-based Two-Factor Authentication
  (RFC 6238, compatible with Google Authenticator).
- **Google Login (OAuth 2.0)**: a full Authorization Code flow implementation
  that signs a user in with their Google account and automatically links to
  an existing email/password account for the same address (no duplicates).
  Works once a free Google Cloud OAuth client ID/secret is added (see README).

## 4. What uses an external service (clearly disclosed)
- The **"Web" tab** calls the Brave Search API to show results from the
  whole internet. Building a crawler/index for the entire web is outside
  the scope of any single student project (Google uses millions of
  servers for this) — so NEXORA plugs into an existing web index for that
  one tab, the same way most real-world apps integrate a search provider.
  Without an API key, NEXORA automatically falls back to a free DuckDuckGo
  search as a working default, then "My Index" if that's unavailable too.
- **AI Verdicts (Fact Check) & AI Project Ideas** call an external AI model
  (Claude) when `ANTHROPIC_API_KEY` is configured. Generating open-ended,
  topic-specific structured content or judging the truth of an arbitrary
  claim isn't something a rule-based program can do reliably — it genuinely
  requires a language model, same as production tools like Perplexity.
- **Google Login** needs a Google Cloud OAuth client ID/secret, since only
  Google can authenticate a Google account — this is true of every app that
  offers "Sign in with Google", not a shortcut specific to this project.

## 5. Tech Stack
- Python 3 standard library only (no external installs needed) for the
  crawler, indexer, ranking, HTTP server, auth/sessions, password hashing
  (PBKDF2), and 2FA (RFC 6238 TOTP implemented from scratch).
- HTML/CSS/JS for the frontend, served directly by the Python server.
- Browser-native Web Speech API for voice search and voice answers.

## 6. Project Structure
The project follows a modular, multi-folder structure (like a real-world
application) instead of one single script:
```
NEXORA/
├── main.py              # entry point
├── app/                  # all Python logic
│   ├── config.py           # settings + API keys
│   ├── crawler.py          # web crawler
│   ├── indexer.py          # inverted index builder
│   ├── ranker.py           # BM25 ranking engine
│   ├── server.py           # web server + all routes/modes
│   ├── auth.py             # accounts, sessions, hashing, 2FA
│   ├── google_oauth.py     # Google OAuth 2.0
│   └── ai.py                # optional AI-powered modes
├── static/                # CSS + JS (frontend assets)
├── templates/              # HTML template
├── data/                   # generated index.json / users.json
├── README.md
└── NEXORA_Project_Report.md
```

## 7. How to Run
```
python main.py crawl     # crawls seed sites, builds data/index.json
python main.py serve     # starts the search engine at localhost:8000
```
